# Hands-on AI Infra

面向 AI Infra 的系统性知识与实践整理，用于后续学习与工程落地。

## 项目简介

本项目用于整理 AI Infra 相关的知识与实践经验，目标不是堆叠资料，而是把碎片化的知识点组织成一张**有深度的知识网络**。每一个知识点都应当回答四个问题：

- 它为什么存在（解决了什么本质问题）？
- 它如何工作（核心机理）？
- 它与哪些技术相邻、替代或互补（网络关系）？
- 它的边界与代价是什么（适用条件、不适用场景、权衡）？

## 为什么做这件事：Agent 时代的判断力

在 Agent 能够快速生成代码与答案的时代，"获取答案"的成本急剧下降，但"判断答案是否正确、是否适配当前场景"的能力反而容易被稀释。AI Infra 恰好是一个判断力极其关键的领域：

- 结论高度依赖**硬件、规模、拓扑、软件版本**，脱离上下文的最优解往往不成立；
- 同一个优化在不同场景下收益可能相反（例如显存与吞吐、延迟与并发）；
- 大量流行"最佳实践"其实是有前提的近似，而非普适真理。

因此本项目坚持：**原理优先、边界清晰、代价明确**。只有理解了机理与约束，人才能在 Agent 给出方案时独立判断，而不是盲从。

## 设计原则

1. **原理驱动** —— 先讲清"为什么"，再谈"怎么做"。
2. **建立关联** —— 每个知识点标注它与上下游技术、替代方案的连接。
3. **明确边界** —— 说明适用条件、不适用场景、代价与权衡。
4. **可验证** —— 尽量提供可复现的配置、实验与数据。
5. **持续演进** —— 与硬件、算子库、框架版本共同更新。

## 知识网络

各领域并非孤立，理解它们之间的依赖关系是构建判断力的关键：

```text
神经网络基础
   │  提供模型结构、复杂度与数值特性（注意力/归一化/MoE 结构等）
   ▼
训练 ────────────────► 推理 ────────────────► 量化
   │                      │                      │
   │  分布式/并行/通信      │  Attention/图/编译/    │  数值格式贯穿训练与推理
   │  决定可训练规模        │  调度决定延迟与吞吐     │  决定显存、带宽与精度权衡
   ▼                      ▼                      ▼
               硬件（算力 / 显存 / 带宽 / 拓扑）与软件栈（框架 / 算子库 / 编译器）
```

- **神经网络基础**决定训练与推理的复杂度与瓶颈位置；
- **训练**的并行与通信策略，直接决定可训练规模与效率；
- **推理**的优化围绕 KV Cache、计算图与调度展开，是延迟/吞吐的主战场；
- **量化**贯穿训练与推理，是显存、带宽与精度之间的核心权衡。

## 使用方式

1. 先读对应领域的**原理**，再看**优化手段**与**权衡**；
2. 关注每个知识点的**边界与代价**，而非孤立结论；
3. 结合可复现实验验证，形成自己的判断，而不是直接采信结论。
